## Part A: Deadline alert emails (signed-in users only)
Goal: bring users back every week with alerts that are useful and honest.

A1. Email settings (Profile page, "Email alerts" section, signed-in only)
- Toggles: Weekly digest (default ON once user opts in), Deadline reminders (default ON), New top matches (default ON).
- Digest day: default Sunday 6 PM user local time (store IANA timezone from browser).
- Explicit opt-in checkbox the first time: "Email me about my saved deadlines and new matches." No emails without it.
- One-click unsubscribe link in every email (signed token, no login needed). Unsubscribe from all + per-type.
- Guests: show "Sign in to get deadline alerts" using the V16.1 dialog.

A2. Email types
- Deadline reminder: saved/tracked roles closing in 7 days and in 2 days. One email per user per day max, bundled. Skip roles marked Applied/Rejected/Hidden.
- Weekly digest: (1) saved roles closing in the next 14 days, (2) up to 5 new top matches added since last digest (same matcher + eligibility rules as the site; never show ineligible roles), (3) tracker counts (saved / applied / interviewing). If nothing to say, don't send.
- Rolling/no-deadline roles: label "Rolling, apply early". Never guess a date.
- Every listing links to its Intern Index detail page (with utm-free ?ref=email param for our own counting) and the real apply link.

A3. Sending ($0)
- Primary: Gmail SMTP from a dedicated sending account via a scheduled GitHub Action (hourly cron picks users whose local send time has arrived). App password stored as a GitHub Actions secret, never in the repo. Respect Gmail's ~500/day limit; queue overflow to next run and log it.
- Abstract the sender (sendEmail(to, subject, html, text)) so we can switch to Resend later when Ty buys a domain, by changing one secret.
- Server-side reads use the Supabase service_role key from a GitHub secret only. Never ship it to the browser.

A4. Data (new migration 20261028000005_email_alerts.sql, RLS on)
- email_prefs(user_id, opted_in, digest, reminders, matches, digest_dow, digest_hour, tz, unsub_token, updated_at). Users can read/update only their own row.
- email_log(id, user_id, type, listing_ids, sent_at, status, error). No user access; service role only. Used for dedupe (never remind twice for the same listing+window).

A5. Email design
- Plain, mobile-first HTML and a text version. Intern Index wordmark, no tracking pixels, no images required. Subject examples: "3 saved internships close this week", "5 new matches for you".
- Footer: why you got this, manage settings link, unsubscribe link, mailing info per CAN-SPAM (use the info Ty provides; leave a TODO placeholder, don't invent an address).

A6. Tests
- Dry-run mode (DRY_RUN=1) renders all emails to ops/email-previews/ without sending.
- Unit tests: timezone scheduling, dedupe, eligibility filter, empty digest skipped, unsubscribe works without login.
- Send one real test to tyfaucher24@gmail.com only after Ty approves.

## Part B: Founder analytics dashboard (Ty only)
Goal: real numbers to show an acquirer (JobGet, Yello, Simplify, WSO, etc.). Cookie-free and privacy-friendly.

B1. Event collection
- Use the analytics table from migration 0003 (run it first if it hasn't been run). Events: visit (daily anon id in sessionStorage, no cookies), signup, sign_in, profile_built, resume_uploaded, save, unsave, apply_click, tracker_status_change, email_open-free metrics (email_click via ?ref=email), unsubscribe.
- No personal data in events beyond user_id for signed-in users. Respect Do Not Track / Global Privacy Control by skipping anonymous visit events.
- Batch inserts, rate-limited by RLS policy, insert-only for anon/auth; select only for admins.

B2. Dashboard page (#admin/stats, admins only via public.admins; non-admins see 404-style "Not found")
- Top cards: total users, new signups (7d/30d), DAU / WAU / MAU, WAU/MAU stickiness, saves this week, apply clicks this week, email subscribers.
- Charts (lightweight, no paid libs): daily signups and active users (90d), signup funnel visit → profile built → signup → first save → first apply click, weekly retention cohorts (week 1–8), top 20 most-saved companies and roles, top schools (counts only, hide any school with <5 users).
- Email section: emails sent, click-through rate, unsubscribes by type.
- Date range picker and "Export CSV" for each table. All numbers computed from real rows; show "Not enough data yet" instead of guessing.
- Aggregations done in Postgres views/functions (security definer, admin-checked) so raw rows never go to the browser.

B3. Tests
- Non-admin and guest cannot read stats (test with anon key).
- Seed data only in a local test DB, never in production.
