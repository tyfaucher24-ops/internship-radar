## 2 — The intro resume drop zone gets the same tick as the Profile page

`V19.md` Part 1 already names `#obDrop`; this section makes it explicit and adds the two intro-only details that don't exist on the Profile page.

- Same four states as the Profile page, same option C visuals: progress ring → green ring → white tick drawn with `stroke-dashoffset` over 420ms → "Resume read" plus up to three real count chips.
- **Where the progress comes from:** both places call `window.readFile`, which `resume-ui.js` already wraps around `RI.analyze`. Emit real progress from that one wrapper so the intro and the Profile page share a single source of truth. Real stages available today: file read, PDF/DOCX text extraction, section parse, field fill. If any boundary isn't observable, advance on the stage that just finished — never a fake timer that creeps to 90%.
- **Intro-specific copy:** step 1's heading is "Start with your resume" and it is optional. So after the tick, the line reads "Resume read — we'll fill in the next steps" and the count chips appear under it. The old "Done. We prefilled what we found. Check it on the next steps." in `#obRs` goes away; that sentence is replaced by the new chip block so it isn't said twice.
- The intro zone stays inside the card and must not push the "Continue" button out of view at 800px height. If the done state makes the card taller than the viewport, let the card scroll (it already has `overflow:auto`) rather than shrinking the ring.
- `role="status"`/`aria-live="polite"` on the state line, announced once per change, exactly as Part 1 says. Reduced motion: instant swap, no ring spin, no tick animation.
- Removing or replacing a resume on step 1 returns that card to the empty state and keeps whatever the student typed on later steps.
- The ring on mobile in the intro card scales to 48px.
