Log as V16 in CHANGELOG. Goal: Ty can make Intern Index public and promote it confidently.
Constraints:
- $0 or near-$0: free tiers only, and list any cost before adding it.

- Keep GitHub Pages as the frontend unless a phase below proves it's a blocker.

## Phase 1: Security and cleanup (launch blockers)
- Admin must not be public: remove admin.html and admin.js from the deployed site (move to ops/ or gate them behind auth from Phase 3), drop the nav and profile-menu link, and add noindex.
- Secrets: none in client code or the repo. Rotate anything found and use GitHub Actions secrets.
- Add security headers via meta where possible (CSP, referrer-policy) and safe external links (rel="noopener").
- Sanitize all listing text rendered as HTML (XSS from posting descriptions) and resume text in the UI.
- Repo cleanup: move old tests to tests/legacy, consolidate CSS layers (v4.css through v15.css) into a clean structure without visual change (screenshot diff each page in both themes), delete dead code, and keep the CHANGELOG.
- Dependency check: vendored libs (pdf.js, mammoth) are current with no known CVEs.

## Phase 2: Data pipeline hardening
- The sync must be reliable unattended:
  - Retries, per-source timeouts, partial-failure tolerance (one bad source never wipes listings), and atomic writes (write temp, validate, swap).
  - A schema validation gate: refuse to publish if the listing count drops more than 15% versus the last run, or required fields are missing.
- Staleness: auto-close listings whose apply link returns 404 or closed (polite checks, rate-limited), and drop past-deadline ones.
- Health: a public-safe status JSON plus a GitHub issue opened automatically on 2 consecutive failed syncs (alerts to Ty). The "Live" badge hides when stale (V15).
- Performance:
  - Split listings into a small index JSON plus lazy detail files (data/detail already exists, so use it), with gzip-friendly output.
  - Initial load under 2.5s LCP on mid-tier 4G mobile, with a Lighthouse perf score of at least 90 on the home page.
- Make sure GitHub Pages and Actions limits won't be hit: repo size, the 1GB Pages limit, Actions minutes (public repo is free), and history bloat from data commits (consider a data branch or squashing the data history).

## Phase 3: Accounts and cloud sync (opt-in, free tier)
Today everything is in localStorage, so users lose their tracker when they switch devices.
- Add optional accounts with Supabase free tier (Postgres plus Auth): email magic link and Google sign-in. Guest mode keeps working fully with localStorage.
- Sync the profile (structured fields only), saved internships, tracker rows, outreach, Autopilot tasks, and preferences. Don't store the raw resume file by default (an opt-in toggle).
- Row Level Security on every table: users can only read and write their own rows. Write tests proving user A can't read user B's data.
- Merge logic on first sign-in (local plus cloud, no data loss) and conflict handling by last-write-wins per row with timestamps.
- Delete account and export my data (JSON) buttons.
- Rate limits and abuse protection on auth.
- Admin role via a Supabase role (gate the admin page behind it).
- If Supabase is rejected for a reason, propose the alternative with a cost before building.

## Phase 4: Legal, privacy and trust (required for a public launch)
- Privacy Policy and Terms pages written for this site in plain English, covering:
  - What we collect and that resumes are parsed on-device.
  - Accounts data, analytics, and data deletion.
  - That listings come from public employer postings and link to the original.
  - That grades are estimates, not guarantees.
  Mark them as drafts for Ty to review, since this isn't legal advice.
- A cookie and analytics notice only if needed.
- A footer with About, Privacy, Terms, Contact, and "Report a broken listing".
- Listing attribution: always link to the employer's real posting. Honor takedown requests via a contact email.

## Phase 5: Analytics, monitoring and feedback
- Privacy-friendly free analytics (e.g. GoatCounter or Cloudflare Web Analytics, with no cookies): page views, sign-ups, saves, Apply clicks, resume uploads, and Feedback page views. No personal data in events.
- Error monitoring: Sentry free tier (scrub personal data), or a tiny self-built error logger into Supabase.
- In-app "Report a problem" and per-listing "Report broken link" that store to Supabase and feed the staleness queue.
- An Admin dashboard (gated): sync health, listing counts, reported issues, and sign-ups.

## Phase 6: Launch polish
- SEO: titles and meta per page, Open Graph and Twitter cards with a share image, sitemap.xml and robots.txt correct, and canonical URLs.
- Make sure the site works with a custom domain later (CNAME-ready, all relative paths). Recommend a domain with its cost (about $10–15/yr), but don't buy one.
- 404 page, offline/slow network states, and loading skeletons.
- Accessibility: axe 0 issues on every page in both themes. Cross-browser: Chrome, Safari (iOS and macOS), Firefox, Edge. Mobile 390px.
- Load test: simulate 500 concurrent users on the static plus Supabase setup and report behavior and free-tier headroom.
