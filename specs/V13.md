## PART 1 — Deadline Autopilot

Goal: the student picks targets (specific internships, or whole companies) and gets a week-by-week apply plan built from real deadlines, with reminders.

### 1.1 Entry points
- "Add to Autopilot" (rocket/clock icon) on every card, the detail modal, the tracker row menu, and company pages.
- "Autopilot" tab in the main nav (next to My Tracker) with a count badge.
- Picking a company = follow all its current listings plus any that open later (matched by `company_id`, optional role-group filter, e.g. "Goldman Sachs · IB only").

### 1.2 Deadline sources and honesty ladder (per target)
Each target gets one `deadlineInfo` with an explicit `kind`:
1. `stated` — deadline published by the source posting. Label: "Apply by Oct 30, 2026".
2. `rolling` — source says rolling. Label: "Rolling — earlier is better". Plan uses a soft target = earliest of (posting date + 21 days, today + 14 days), labelled "Suggested target (rolling)".
3. `expected` — no stated date, but we hold REAL past-cycle data for this company + role group (from `data/sync_history.json` / `changes.json` first-seen/closed dates, ≥1 prior cycle). Label: "Expected ~Nov 10 (based on 2025 cycle: opened Aug 4, closed Nov 12)". Always shows the basis and an "Expected" tag; never styled like a stated date. Confidence: high (≥2 cycles within ±7 days), medium (1 cycle), shown in tooltip.
4. `unknown` — no stated date, no past data. Label: "Deadline not listed". Plan uses no apply-by date; instead it front-loads prep and adds a "Check posting weekly" task, plus a user field "Set my own target date" (stored as `userTarget`, labelled "Your target").
- When a stated date appears in a later sync, it replaces expected/unknown automatically, and the plan re-flows with a notice: "Real deadline posted: Oct 30 (was expected ~Nov 10). Plan updated."
- A company that has not opened its posting yet: "Not open yet — expected to open ~Aug 4 (2025 cycle)" only with real data; otherwise "Opening date unknown — we'll alert you when it appears".

### 1.3 Plan generation (pure function `autopilot-core.js`, unit-tested)
Input: targets + profile (class year, resume present?, experience) + today. Output: weeks (Mon–Sun, user's local TZ) each with tasks.
Task types and default offsets from the apply-by date (D):
- `prep` (research company, role, recent news) — D−21 to D−14
- `resume` (tailor resume: keyword gaps from grader v2 "What to improve" bullets) — D−14 to D−10
- `network` (reach out to 2–3 warm paths from Part 2) — D−21 to D−7
- `cover` (cover letter / short answers, only if the posting asks) — D−10 to D−5
- `apply` — target D−3 (buffer), hard D
- `followup` — applied + 7 days (matches tracker default)
- Rules: compress proportionally if D is < 21 days away; if D < 3 days, single "Apply now" task flagged red. Load-balance: max 5 tasks/week by default (user setting 3–10); overflow pushes prep earlier, never past D. Past-due tasks roll to "Overdue" not deleted.
- Group tasks for the same company. Week view header: "Week of Oct 26 · 4 tasks · 1 deadline".

### 1.4 Data model (localStorage key `autopilot`, version 1)
```
autopilot = {
  v: 1,
  settings: { maxTasksPerWeek: 5, weekStart: "mon", remindersOnSite: true,
              email: { enabled:false, address:null, verified:false },
              sms:   { enabled:false, phone:null,  verified:false },
              quietHours: ["21:00","08:00"] },
  targets: [{ id, type:"listing"|"company", listingId?, companyId?, roleGroups?:[],
              addedAt, deadlineInfo:{ kind:"stated"|"rolling"|"expected"|"unknown",
              date?, basis?:{cycles:[{year,opened,closed}]}, confidence? },
              userTarget?, paused:false }],
  tasks: [{ id, targetId, type, title, start, due, done:false, doneAt?, snoozedTo?, source:"auto"|"user" }],
  reminders: [{ id, taskId, at, channel:"site"|"email"|"sms", sentAt?, dismissedAt? }]
}
```
- Tracker link: completing `apply` sets the tracker row to Applied with dateApplied; tracker status changes (Rejected/Offer) close the target's remaining tasks.
- Export/import via existing `store.js` export (app id unchanged for compatibility).

### 1.5 Reminders
- On-site (no login, ships now): bell icon in header with unread count; on load, show due/overdue tasks in a small dismissible panel; optional browser Notification API (permission asked only after a user click, never on load); optional `.ics` export per task and a full-plan "Add to calendar" `.ics` (generated client-side; Google/Apple/Outlook compatible).
- Email/text (optional, BLOCKED on Ty): requires the optional login + the Resend API key Ty still has to provide (and an SMS provider decision for text). Until provided: UI shows "Email reminders — coming soon" disabled toggle with tooltip; no keys in the repo ever; sending runs server-side (existing `railway_function.ts` style), double opt-in verification, one-click unsubscribe in every message, daily digest by default (not one email per task), quiet hours respected, CAN-SPAM/TCPA compliant copy.

### 1.6 UI
- Autopilot page: left = targets list (logo, company, role, deadline chip by kind: green "Apply by", grey "Rolling", amber outline "Expected", muted "Not listed"); right = week-by-week timeline (vertical, current week pinned at top, "Overdue" strip in red above it). Each task: checkbox, title, company, due date, "why" tooltip, snooze (1d/3d/1w), edit date.
- Header stats in stock-quote style: "Targets 8 · This week 4 · Next deadline Oct 30".
- Empty state: "Pick internships or companies and we'll build your plan" + button to the database filtered by profile matches.
- Detail modal: compact "Autopilot" panel showing the 3 next tasks for that listing.

### 1.7 Edge cases
- Listing closes/removed before D: target marked "Posting closed", tasks cancelled, notice shown; company targets stay active.
- Deadline moved earlier/later by source: re-flow, notice with old→new.
- Deadline already passed when added: refuse with "This deadline has passed" + offer to follow the company for next cycle.
- Time zones: dates are date-only; deadlines without time treated as 11:59 PM local. DST-safe date math (no ms arithmetic across days).
- 50+ targets / 500 tasks: still renders < 100 ms (virtualize timeline).
- Same company multiple listings: shared prep/network tasks deduped.
- Storage disabled: in-memory with banner "Your plan won't be saved in this browser".
- Never displays an expected date without its basis text.

### 1.8 Tests
- Unit: plan generation for D in 2/10/21/60 days; compression; load-balancing cap; each deadline kind; expected requires ≥1 real cycle (fixture without history → unknown); re-flow when stated date appears; DST boundary weeks; overdue roll.
- Playwright: add from card/modal/tracker; company follow; complete apply → tracker Applied; snooze; ics download valid (parse with `icalendar`); reminder panel on reload; notification permission only after click; email toggle disabled without key; reduced motion; axe 0.
- Data test: every `expected` in production data has `basis.cycles.length ≥ 1` traceable to sync history.

## PART 2 — Warm-Path Finder

Goal: for each company, show realistic ways in (alumni, sport teammates, clubs) and a ready-to-edit outreach message — designed honestly.

### 2.1 Hard constraint (state in UI + README)
There is no legal way to pull LinkedIn alumni data automatically (LinkedIn ToS forbids automated collection; no public API for this). We do NOT collect, store, or display LinkedIn people data. We NEVER fabricate people, names, titles, or counts of alumni.

### 2.2 Sources of warm paths (all honest)
1. Deep links (zero data stored): buttons that open LinkedIn people search pre-filtered, built from profile + company:
   - Alumni: `https://www.linkedin.com/search/results/people/?keywords=<Company> <School>` and the school's Alumni page `https://www.linkedin.com/school/<school-slug>/people/?keywords=<Company>` when the slug is known (curated map in `data/schools.json`, no guessing; fall back to keyword search).
   - Sport: keywords `<Company> <School> lacrosse` (e.g. for Ty: "Queens University of Charlotte lacrosse").
   - Clubs/Greek/major: keywords from profile clubs.
   - Labelled "Opens LinkedIn search — results come from LinkedIn, not us."
2. User-entered contacts: "Add a contact" (name, company, role, how you know them: alumni/teammate/club/family/other, LinkedIn URL optional, email optional, notes). Stored locally only.
3. Optional opt-in community directory (later phase, requires login): students/alumni choose to list themselves ("Queens '24, lacrosse, now at Wells Fargo — happy to chat"), explicit consent, can edit/delete anytime, visible only to logged-in users, report/block, rate-limited contact via relay (no raw emails shown). Empty until real people opt in; show "No one from your school has joined yet" — never seeded with fake entries.
4. Other honest paths: company campus-recruiting page / events link if present in our data; school career-center link (from `schools.json` if curated).

### 2.3 Outreach message templates
- Templates: LinkedIn connection note (≤300 chars, live counter), LinkedIn message, cold email, alumni email, teammate/athlete email, follow-up (7 days), thank-you after call.
- Personalized from profile tokens: `{first_name} {school} {class_year} {major} {sport} {club} {company} {role} {contact_first_name} {shared_link}`. Missing tokens are removed gracefully (no "{sport}" leakage, no "a D1 athlete" if not set).
- Example (athlete): "Hi {contact_first_name} — I'm {first_name}, a {class_year} {major} student and {sport} player at {school}. I saw you went from {shared_link} to {company} and I'm applying to the {role} internship. Would you be open to a 15-minute call about your path?"
- Editor: editable textarea, Copy button, "Open in LinkedIn" (opens profile/search; we never auto-send), "Open in email" (`mailto:` with subject/body). Tone selector (formal / friendly). No AI-invented facts about the contact.

### 2.4 Outreach tracking (tied to tracker)
Data (localStorage `warmpaths`, v1):
```
contacts: [{ id, name, companyId, company, role?, relation:"alumni"|"teammate"|"club"|"family"|"other",
             linkedinUrl?, email?, notes?, createdAt }]
outreach: [{ id, contactId, trackerRowId?, targetId?, channel:"linkedin"|"email"|"other",
             template, status:"drafted"|"sent"|"replied"|"call_scheduled"|"referred"|"no_reply",
             sentAt?, followUpAt?, history:[{status,at}] }]
```
- Tracker gets an optional "Contacts" column (count + latest status chip) and the row drawer shows outreach history. Autopilot `network` tasks link to the warm-path panel and complete when an outreach is marked sent. Follow-up defaults to sent + 7 days, shown as an Autopilot task/reminder.
- Marking "referred" adds a "Referral" tag to the tracker row.

### 2.5 UI
- Detail modal + company page: "Ways in" panel: sections Alumni / Teammates / Clubs / Your contacts / Company recruiting, each with deep-link button(s) and count of YOUR saved contacts only. Profile gaps prompt: "Add your sport to find teammates".
- "Outreach" sub-tab in My Tracker: table of contacts × status with filters.

### 2.6 Privacy
- Contacts stay in the browser; never uploaded unless the user logs in and turns on sync. Export/delete all in one click. No third-party trackers on these pages. Deep links send nothing to us. Community directory: consent screen, GDPR/CCPA-style delete, minimum data.

### 2.7 Tests
- Unit: URL builder encodes names (`&`, accents, "AT&T"), uses curated school slug only when present; template rendering removes missing tokens; 300-char counter.
- Playwright: Ways-in panel shows deep links with correct URLs (assert hrefs, do not hit LinkedIn); add/edit/delete contact persists; outreach status changes update tracker column + Autopilot follow-up; mailto body correct; no network request to linkedin.com on page load; empty directory shows honest empty state; axe 0.
- Static check: repo grep — no hard-coded person names in data/ or templates; no "scrape".

### 3.2 Onboarding flow (`onboarding.js`, overlay over the planet scene)
Panel: centered card 640px wide on `#232a33`, radius 16, planet dimmed/zoomed behind it. Top: progress bar (5 segments, green fill) + "Step 2 of 5". Every step: Back, Continue (primary), "Skip" (text button). Top-right "Skip setup →" exits to home anytime. Data saved to `profile` after every field change (debounced 300 ms), so leaving mid-way loses nothing.
1. Resume (optional): drag-and-drop zone ("PDF or DOCX · parsed in your browser — never uploaded"), uses existing `resume.js`. After parse, show "We found: School, Major, GPA…" chips with "Check these" for low-confidence fields; prefill next steps.
2. School: school (typeahead from `data/schools.json`), major, class year (chips 2027–2030), GPA (optional, 0–4.0 validation, "Prefer not to say").
3. Interests + locations: role-group chips (IB, PE, Quant, SWE, Data, Product, Consulting, Marketing, Finance/Accounting, Engineering, Health, Government, Research…), locations chips + "Remote ok" toggle; term (Summer 2027 default).
4. Experience: quick-add internships/jobs/leadership/athletics (sport + level, e.g. "D1 Lacrosse"), clubs. Prefilled from resume.
5. Reveal: "Your top matches" — the planet zooms; top 5 real listings from match-core with grade pill (e.g. "86% · A"), company, role, location, deadline label (per Part 1 kinds). If no profile data was given: show "Most popular closing soon" honestly labelled. Button "See all my matches" → homepage with personalized grades column on; secondary "Start Autopilot for these" (Part 1).

### 3.3 Animation spec
- Intro → step 1: hero copy fades/slides up 12px (300 ms, `cubic-bezier(.2,.8,.2,1)`); planet scales to 0.85 and shifts right 18% (600 ms); card rises from 24px below with opacity 0→1 (400 ms, 120 ms delay).
- Step → step: outgoing content translateX(−24px)+fade (220 ms), incoming from +24px (260 ms); Back reverses direction. Card height animates with a FLIP (no jump). Progress bar fill width transition 400 ms; completed segment pulses green once.
- Chip select: scale 0.96→1 (120 ms), green border for selected.
- Reveal: planet rotates toward the US, dots for the 5 matches brighten green and "ping" (staggered 80 ms); match rows count-up their % (600 ms, like a stock quote ticking) and slide in staggered 60 ms.
- Exit to home: card fades, planet dissolves into the market bar (existing `.fade`).
- Performance: transform/opacity only, no layout-affecting animation, 60 fps, no long tasks > 50 ms; WebGL globe paused while card is static.
- Reduced motion: all transitions become 150 ms opacity crossfades; no zoom/rotate/ping/count-up (final numbers shown instantly); progress bar jumps.

### 3.4 Accessibility
- Onboarding is a `role="dialog"` with `aria-modal`, labelled by step heading; focus moves to the step heading on each step; focus trap; Esc = "Skip setup" with confirm-less exit (data kept).
- Progress bar `role="progressbar"` with aria-valuenow/max and text "Step 2 of 5".
- Chips are toggle buttons with `aria-pressed`; drop zone is a real `<input type=file>` button, keyboard operable.
- Live region announces parse results and the reveal ("5 matches found").
- AA contrast in dark mode; 44px min targets.

### 3.5 Edge cases
- No resume, skip everything → home with no grades and a gentle "Add your profile for match %" bar.
- Resume parse fails/scanned PDF → "Couldn't read this file — fill in the next steps instead", no junk in fields.
- Storage disabled → works in memory with a notice.
- Existing V12 profile → onboarding prefilled; never overwrites without confirmation.
- Fewer than 5 matches → show what exists; zero → honest empty state with "Broaden locations".
- Mobile (secondary): card becomes full-screen sheet.

### 3.6 Tests
- Playwright: both intro buttons route correctly; "Free forever · no login needed" visible; counter equals meta.json `open`; each step skip/back/continue; data persists across reload mid-flow; resume fixture prefill; reveal shows real listing ids present in listings.json; homepage shows grades after finish; Esc exits; reduced-motion run (emulateMedia) has no transforms > 150 ms; axe 0 on every step; screenshots at 1440×900 for each step; no CLS on step change (layout-shift observer = 0).
