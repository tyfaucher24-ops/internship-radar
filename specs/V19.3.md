## The real bug (measured, not guessed)

Intro step 2, typing `unc` in School: the suggestion rows are cut in half and the list sits on top of the "Major" and "GPA" labels.

Cause is a CSS specificity accident in `site.css`:

- Line 902–904 styles `#intro.v13 .obcard .sugg ul` (the list) with `top:calc(100% - 20px)` — it tugs the list 20px **up**, over the input.
- Line 964–966 then styles `#intro.v13 .sugg` — the **wrapper div**, not the list — with `position:absolute; padding:4px; border:1px; border-radius:12px; box-shadow:…; max-height:240px; overflow:auto`. So the wrapper becomes a small absolutely-positioned box that also paints a border and shadow, and it **clips** the taller list inside it. Measured on 1440: wrapper `clientHeight` 88 with `scrollHeight` 172 — over half the list is clipped.

The same 964 rule also overrides `#intro.v13 .ta{position:relative}` on step 3's Interests and Locations wrappers, because both selectors have identical specificity and 964 comes later. So step 3 has the same defect even though its markup is different.

## PART 1 — Intro suggestion lists: in flow, bigger, never covering anything

Target: a typed suggestion list pushes the rest of the form down instead of floating over it. Nothing is ever clipped, and the words below are never covered — that is the actual complaint.

Replace the intro block (currently lines ~902–904 and ~964–966) with one set of rules:

```css
/* V19.3: the wrapper is only a positioning parent — it must never paint or clip */
#intro.v13 .obcard .sugg,
#intro.v13 .sugg{
  position:relative;display:block;margin:0 0 18px;padding:0;
  border:0;background:none;box-shadow:none;max-height:none;overflow:visible;list-style:none;
}
#intro.v13 .obcard .sugg .in,#intro.v13 .sugg .in{margin-bottom:0}
/* V19.3: the list is in flow, so it can never cover the next field's label */
#intro.v13 .obcard .sugg ul,#intro.v13 .sugg>ul{
  position:static;left:auto;right:auto;top:auto;margin:8px 0 0;padding:8px;list-style:none;
  background:#fff;border:1px solid #e3e6ef;border-radius:14px;
  box-shadow:0 6px 18px rgba(15,23,42,.10);
  max-height:min(300px,44vh);overflow:auto;
}
#intro.v13 .obcard .sugg ul li,#intro.v13 .sugg>ul li{
  display:flex;align-items:center;min-height:52px;padding:13px 16px;border-radius:10px;
  font-size:16px;line-height:1.35;color:#14172b;white-space:normal;overflow-wrap:anywhere;cursor:pointer;
}
#intro.v13 .obcard .sugg ul li+li,#intro.v13 .sugg>ul li+li{margin-top:2px}
#intro.v13 .obcard .sugg ul li:hover,
#intro.v13 .obcard .sugg ul li[aria-selected="true"]{background:#f5f3ff}
```

Verified on the live copy at 1440 and 390 before writing this: gap under the input 8px, row height 52px desktop, no clipping (`scrollHeight <= clientHeight`), and after clicking a suggestion the "Major" label sits below the list with nothing on top of it. Long school names wrap to two lines instead of being cut.

Keep the existing keyboard behaviour untouched: arrows, Enter, Escape, `aria-activedescendant`, `aria-expanded`. Only the box model changes. If the list pushes the card past its height, the card already scrolls (`overflow:auto`) — confirm the Continue button is still reachable at 800px tall.

## PART 2 — Every searchable dropdown on the site (`combo.js`): rows and panel, bigger

This is the "all of the other search boxes" half. Today a row is 40px tall at 15px with the label forced to one line (`white-space:nowrap` + ellipsis), and the panel is at minimum 280px wide. A long school or major name gets chopped, and the panel is narrower than the 52px fields it belongs to.

Change, in `combo.js` and `site.css`:

- `const ROW=40,VIS=9` → `const ROW=48,VIS=7`. The virtualization math uses `ROW` for row `top` and the pad height, so the constant must change with the CSS or rows will overlap.
- `.cb-o,.cb-h{height:40px}` → `height:48px`, padding `0 12px`, font-size `var(--fs-m)`.
- `.cb-t` keeps `overflow:hidden` but becomes two-line clamp: `display:-webkit-box;-webkit-line-clamp:2;-webkit-box-orient:vertical;white-space:normal;line-height:1.35;`. No ellipsis mid-name; a long label wraps to two lines inside the 48px row. If a name still needs a third line, that is what `title` is for: set `title="<full label>"` on each row.
- `.cb-search` height `44px` → `48px`, font-size `var(--fs-m)`.
- `.cb-pop` `min-width:280px` → `340px`, `max-width:min(520px,calc(100vw - 16px))`, padding `10px`.
- `.cb-list` max-height `360px` → `336px` (seven rows). Keep `.mf8 .cb-list` and `.fpanel .cb-list` caps, just scale them: 200→240 and 260→288.
- `.cb-field` stays 52px where it already is; where it is 48px (filter panels, tracker bulk-status), raise to 52px so the field and its panel rows match.
- `.cb-sbox{margin-bottom:8px}` → `10px`; keep the magnifier icon centred on the taller input.
- The tiny paired fields (Graduation month/year are 96px wide inside `.pf-row2.tight`) must still open a 340px panel without going off screen; `place()` already shifts and clamps, so verify rather than change the logic.

Do **not** change the search ranking, the fuzzy match, the "Other:" row, the pinned "Popular" grouping, or the multi-select chips. This is sizing only.

## PART 3 — Quick search (Ctrl K): rows a person can read

`#qkIn` is 44px and each result is 39px with a one-line ellipsis, so a long internship title is unreadable.

- `#qkIn` height `44px` → `52px`, font-size `var(--fs-l)`… if that looks too big at 390px, use `var(--fs-m)` on mobile and `var(--fs-l)` above 700px.
- `.qk-res li`: `min-height:48px`, `padding:12px 14px`, `font-size:var(--fs-m)`, `line-height:1.4`, and the title allowed to wrap to **two** lines (`-webkit-line-clamp:2`) instead of a hard ellipsis. The company stays bold. `.qk-res` max-height `320px` → `360px`.
- The "No open internships match." row and the keyboard hint get the same 48px floor so nothing jumps when results appear.
