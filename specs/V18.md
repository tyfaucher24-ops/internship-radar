## PART 1 — DATA ACCURACY (fix first; everything else is cosmetic next to this)

### 1.1 Trust rule, written into the code
A listing may only be shown as Open if it was confirmed on its source within the last 72 hours. Otherwise it shows as "Check date unknown" and is filtered out of Open by default. Never show a listing as open on the strength of an old check.

### 1.2 Fix the known gaps (measured on the live data on 2026-11-04, use these as the baseline and report the after numbers)
- Open listings: 13,746.
- **1,626 open listings have no `last_verified` at all**, and another 110 are older than Nov 1. Give every listing a verified date from the sync, or close it. Target: zero open listings without a check in the last 72 hours.
- **3,024 open listings have `has_desc: false`** (no posting text). Fetch the posting text for all of them, so the detail panel and the grader have something real to read. If a board doesn't serve text, mark it "Description not available from this employer" rather than leaving a blank space.
- **151 duplicate rows** across 149 company+title+location groups among open listings. Dedupe on a normalized key (company, title, city, state, season), keep the most recently verified row, and keep the stable id the tracker points to. Report the count after.
- **Applied links:** 9,125 of 13,746 open listings have no `apply_ok_at`. Run a HEAD/GET check over every apply link with the existing link checker, record last-OK time, and mark any 404/410 as closed. Add a visible "Apply link checked <date>" line in the panel.
- **1598 open listings have `apply_kind: none`** (no apply route resolved). Either resolve the company posting URL, or hide the Apply button and show "Apply on the company site" linking to the careers page. Never leave a dead or missing Apply button.
- **Deadlines:** only 2,028 open listings carry a deadline. Parse real close dates from posting text and ATS fields only. If a posting is rolling, say "Rolling, apply early". Never estimate a date, never copy a season into a deadline field. Keep `deadline_source` visible in the panel on hover or under "Where this came from".
- **Season/year:** 7,594 open listings have no season. Infer only from explicit title or text ("Summer 2027", "Fall Co-op"), never from the posting date. Unknown stays "Season not listed".
- **Category "Other":** 2,108 of 13,746 open listings fall into "Other". Improve the classifier so Other drops below 8%, using title and description tokens with a hand-checked test set of 200 listings and a precision floor of 90% on the categories you emit.
- **Location parsing:** fix the known Vancouver, WA bug and any state/city mismatch. Every location must parse to a real US city+state or "Remote (US)". Postings with multiple offices must list up to 6 and then "and N more". Anything non-US gets dropped, with the count logged.
- **Stale-term guard:** an open listing whose term has already passed (for example Summer 2026 in November 2026) must be closed or moved to "Past terms" and hidden by default.

### 1.3 A visible accuracy system
- Add `ops/data-health.json` (already exists as data/health.json — extend it) with: open count, % verified in 24h, % with deadline, % with description, % "Other" category, duplicate count, dead-link rate from the daily check, per-board failure counts. Show a compact version on the site: a small "Data health" line in the footer with real numbers, e.g. "13,746 open · 96% checked today · 0.4% dead links".
- If any number falls below its floor (verification < 90% in 72h, dead links > 2%), the sync fails loudly in the Actions log and the site shows "Some listings may be out of date" with the last good timestamp. Honest over pretty.
- Add a per-listing "Report a problem" that actually files into Supabase now (not just a GitHub issue link) with reason chips: closed / wrong deadline / wrong location / broken link. Three reports of "closed" hides it until rechecked.

### 1.4 Sync reliability
- `sync5.yml` and `email-alerts.yml` have to be in `.github/workflows`. If they are not, say so in the build report with the exact file names Ty must upload.
- The 8% removal guard stays, but log which boards drove removals. If one board drives more than 30% of removals, pause it and flag it in the health file instead of trusting it.
- Target: no board unverified longer than 48h.

## PART 2 — VISUAL DESIGN (make it look like a product, not a project)

Benchmark to hit: the calm density of Linear, the clarity of Stripe's dashboard, the trust of AirBnB's listing cards, the scannability of Levels.fyi, the speed of Simplify's list.

### 2.1 Design system, written down and used
- One `tokens.css` with named tokens: color (surface, surface-2, border, text, text-muted, accent, success, warn, danger), spacing scale (4/8/12/16/24/32/48/64), radii (6/10/14/999), type scale (12/14/16/20/24/32/40), shadow scale (3 levels), and motion durations (120/180/240ms). Nothing hardcoded anywhere else. Add a `docs/DESIGN.md` page listing the tokens and showing them rendered.
- Type: one sans family (system stack first: `ui-sans-serif, -apple-system, "Segoe UI", Roboto, Inter`), max 2 weights per view, line-height 1.5 for body and 1.2 for headings, max line length 68 characters for prose.
- Contrast: every text/background pair at AA or better in both themes. Automated check in CI that parses the token pairs and fails on any pair under 4.5:1 (3:1 for large text).
- Focus: a visible 2px accent ring on every interactive element, never `outline: none` without a replacement. Tab order follows reading order on every page.
- Dark and light both look designed, not inverted: no pure black (`#0b0d10`-ish), no pure white cards on white background; borders carry the separation instead of heavy shadows.

### 2.2 The listing list (the most-used screen)
- Card anatomy, identical everywhere: company mark or monogram, company name, role title (2-line clamp with ellipsis, per Ty's earlier approval), location line (city, state · Remote tag), deadline chip with real urgency color (30+ days neutral, 8–30 amber, ≤7 red, rolling gray), season chip, one-line salary if listed, save button and Apply at the right, and a small checked-date footer.
- Row height and rhythm consistent to the pixel. Hover = one subtle surface lift, not a jump. Selected = accent left border.
- Skeleton loaders shaped like the real cards (not spinners) and shown only past 150ms so fast loads don't flash.
- Empty state that helps: "No matches for 'X' in Ohio" plus three real escapes: clear that filter, see remote roles, see roles closing this week. Never a blank panel.
- Infinite scroll with a "You've seen all 13,746" end state, plus a jump-to-top button after 2 screens.
- Keyboard: `/` focuses search, `j`/`k` walk the list, `s` saves, `Enter` opens the panel, `Esc` closes. A `?` sheet lists the shortcuts.

### 2.3 The detail panel
- Order: title, company, location, deadline, Apply (primary), Save, then eligibility facts, then description, then "Where this came from", then report.
- Facts grid with honest blanks ("Not listed") in a muted style, never dashes with no explanation.
- If the description is long, collapse past 400 words with a "Read the full posting" expand (no scroll trap).
- On mobile it becomes a full-height sheet with a drag handle and a sticky Apply bar at the bottom.

### 2.4 Navigation and page chrome
- One header, one pattern: logo left, primary nav (Find, For you, Tracker, Profile), search, theme toggle, account. Sticky on scroll with a hairline border appearing only after scrolling. Collapses to a bottom tab bar on phones (Find, For you, Tracker, Profile) with the current tab clearly marked.
- Breadcrumbs or a clear back on every deep page. Never strand the user.
- Footer with real links (About, Privacy, Terms, Feedback, Data health, Contact), plus a one-line honest pitch. No dead links, no `#` placeholders.
- Consistent page titles (`Find · Intern Index`), and every page reachable by URL.

### 2.5 Onboarding, empty, and error surfaces
- First visit: no tutorial (Ty removed it). Instead a single, skippable 3-field inline starter under the search ("School, class year, target field") that improves matches on the spot, with "Skip for now" always visible.
- Guest mode with the existing V16.1 "Sign in to save" prompt, one toast maximum per session.
- Every error in plain words, with a next step: no raw Supabase messages, no "Error 500". Example: "We couldn't save that. Your other saves are safe. Try again." with a Retry button.
- Offline or failed data fetch: show the last good cached copy with "Showing a saved copy from <time>" instead of an empty page.
- Loading a slow resume: step text ("Reading your resume…", "Finding your strongest matches…"), no fake progress bars that sit at 90%.

### 2.6 Micro-interactions, used sparingly
- Save: the heart/badge fills with a 120ms scale pop and the count ticks. Nothing else animates on save.
- Filter chips slide in and out; counts animate only when they actually change.
- Respect `prefers-reduced-motion` everywhere.
- No confetti, no bouncing, no attention-seeking animation. Calm and fast reads as expensive.

### 2.7 Mobile first (most students will open this on a phone)
- Test at 390, 430, 768, 1024, 1280, 1440.
- 44px minimum tap targets, 16px minimum input font size (no iOS zoom), safe-area insets respected, no horizontal scroll anywhere.
- Filters in a bottom sheet with a sticky "Show N results" button that always shows the live count.
- Sticky Apply bar on the detail sheet so the primary action is never off-screen.

## PART 3 — UX AND PRODUCT FLOW

### 3.1 The five-minute first session
Target: a brand-new visitor gets a graded profile and their top 10 matches inside five minutes without signing up.
- Path: land → see the list is real (count and 3 sample cards visible immediately) → upload resume or fill 4 fields → grade and matches appear on the same page → save one → get the one-time sign-in prompt.
- Track the funnel (already in V17 analytics) with the goal: 40% of new visitors build a profile, 25% save something, 10% sign up.

### 3.2 Clarity of the grade
- One sentence under the grade explaining what it means in plain English ("B+ means you're competitive for most target roles, and reach roles are in range"). No jargon.
- Every match card shows *why*: two real reasons maximum ("Fits your finance background", "Accepting sophomores"), plus one honest risk when it exists ("Usually wants a prior internship").
- Never show a role the student isn't eligible for in top matches. Eligibility unknown is not "ineligible": show it, labeled "Eligibility not listed".

### 3.3 Search that behaves
- Instant results, 40ms debounce feel, typo tolerance ("Gldman" finds Goldman Sachs), company aliases (Goldman → Goldman Sachs), and stemmed titles ("intern" → "internship").
- Suggest chips after each search: "finance internships in Charlotte", "remote data roles closing this week".
- Remember recent searches locally, clearable.
- Search must cover company, title, city, state, and description tokens.

### 3.4 The tracker
- One-click add from any card, one-click status change, and a CSV export that opens cleanly in Excel (already there — verify on a 500-row export).
- The empty tracker teaches by doing: "Save your first role and it lands here" with a single real suggested role for that user.

### 3.5 Trust and the "is this real" test
A skeptical student should be able to answer, within 10 seconds on any card: who is this company, is this posting real, when was it checked, and does this link go to the employer. Anything that blocks those answers is a bug.

## PART 5 — SEO AND FINDABILITY (this is how you actually get users)

- Per-page `<title>`, meta description, canonical, and Open Graph tags with a real 1200×630 share image showing the product (generate it, don't fake a screenshot). Also Twitter card tags.
- JSON-LD on listing detail pages: `JobPosting` with title, hiringOrganization, jobLocation, validThrough, employmentType, datePosted, and a direct-apply URL. Only include fields you actually have.
- `sitemap.xml` covering home, find, and a crawlable page for the top 500 companies (e.g. `/company/goldman-sachs`), each listing real open roles. Static generation, no client-side rendering for these.
- Structured internal linking: company pages, category pages (`/internships/finance`), city pages (`/internships/charlotte-nc`) built from real data with at least 20 open roles each, or not built at all.
- robots.txt allows all of it, sitemap referenced. No cloaking.
- A real 404 page that helps: suggests search and three popular categories.
