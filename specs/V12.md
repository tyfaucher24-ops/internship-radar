## PHASE 2 — Data accuracy (the core product)
Goal: the most accurate internship database on the market.
1. Accuracy audit: pick 200 random live listings (stratified by source, industry, and company size). For each, open the source posting and check it's still open, plus company, title, location, deadline, apply URL, pay if listed, and sponsorship if listed. Record the results in ops/V12_ACCURACY.md. Target ≥99% all-fields-correct. Fix root causes, not just individual rows.
2. Closed-listing detection: anything that 404s, redirects to a generic careers page, or says "no longer accepting" gets removed within one full sync. Measure the time-to-removal.
3. Dedupe: no duplicate listings (same company + normalized title + location + term). Similar roles are grouped correctly with no wrong merges. Spot-check 50 groups.
4. Classification: every listing has a correct role group (IB, PE, quant, SWE, data, product, consulting, marketing, finance/accounting, engineering disciplines, health/nursing, government, research, etc.), term (Summer 2027 / Fall / Spring / co-op), and level (freshman-friendly, sophomore, junior, MBA/PhD excluded or tagged). Spot-check 200, target ≥97%. MBA/PhD/full-time roles must NOT show as undergrad internships.
5. Coverage: re-run the top 300 employer audit and finish it. Report covered / not covered and the reason. Find legitimate routes for blocked firms (official APIs, schema.org JobPosting, official RSS/XML feeds, or public ATS endpoints). Never bypass bot checks or robots.txt. If a firm can't be covered, show "Apply on company site" with a link to their careers page so users still find it.
6. Deadlines: raise the share of listings with a real deadline wherever the source states one. Never guess. "Opens around X" predictions are labeled Expected and show their basis.
7. Locations: normalized city/state, remote flagged, and every listing in the USA.
8. Logos: correct logo for each company. Spot-check 100 for wrong-company logos.
9. Counts everywhere (header, market bar, filters, results) must agree exactly, from one source of truth.
10. Ticker/Market: every event matches a real diff. Verify 50 events against the sync reports.

## PHASE 3 — Resume parser and grader accuracy
1. Parser: create a NEW held-out set of at least 40 resumes never used for tuning (varied formats: one/two-column PDF, DOCX, scanned-text PDF, Canva-style, athlete, international, community college, career changer, grad-year edge cases, double major, minors, no GPA). Score field-level accuracy honestly. Target ≥97% on held-out. Low-confidence fields stay empty and are flagged in the "Check these" review. Nothing junk ever lands in a field (school only from the list, GPA numeric 0–4.0 (or converted from 0–5/100 scales with a note), class year valid).
2. Skills: replace keyword matching with role-aware skill extraction and matching (e.g., AI/ML roles shouldn't credit Excel as a core match). Use synonyms and a skill taxonomy, and weight skills by importance to the role group.
3. Grader calibration: build a calibration set of at least 30 realistic profiles × 30 listings across tiers. Grades must be believable to a career-services advisor:
   - A strong sophomore (3.9 GPA, D1 athlete, relevant clubs) should NOT get an F at bulge-bracket sophomore programs. A low-but-real-shot grade (around D+/C-) with an honest explanation fits better, and a separate tier note can explain how competitive the program is.
   - Elite roles stay hard; realistic small-company roles reward fit.
   - Grades are stable: small profile edits shouldn't swing them wildly.
   - Separate "Fit" (how well you match) from "Odds" (competitiveness) in the panel so users understand why.
4. Feedback quality: every line cites real profile and listing data (keep the 100% check). Add specific, actionable next steps (e.g., "Add your investment club valuation project with numbers", "Apply by Nov 15; this firm fills early", "Reach out to alumni: X people from your school work here" only if real data exists). Never generic filler, never invented facts.
5. Low-confidence handling: thin profile or thin listing gives "Not enough info" plus exactly what to add.
