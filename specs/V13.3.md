## 6. LISTING DATA ACCURACY + FRESHNESS (equally important)
Every listing must be correct and current. Wrong or dead listings kill trust.
- Audit: sample 100 random open listings, open each official source, and check company, title, location, season/year, deadline, and that the posting is actually live. Report accuracy % per field; target is 98% or better and 0 dead links shown as open.
- Liveness: re-check every open listing's source URL/ATS on each full sync. If 404, closed, or removed from the ATS feed, mark it Closed within one sync (2h max). No stale Summer 2026 or past-season listings shown as open.
- Deadlines: only show a deadline that is stated by the source. Otherwise show "Rolling" or "No deadline listed." Never guess. Show "Verified X hours ago" on every listing.
- Fields: normalize locations (City, ST / Remote / Hybrid), clean titles (no HTML or codes), correct season and year, dedupe the same role posted on multiple boards (keep the official ATS link).
- Coverage: list which companies/ATS sources failed in the last sync, retry them, and expand official ATS sources (Greenhouse, Lever, Ashby, Workday, SmartRecruiters) where allowed. Respect robots.txt and terms; no bot-check bypassing.
- Monitoring: a sync health log (counts added/closed/failed per run) plus a CI check that fails if the open count drops or jumps more than 30% in one run, or if more than 2% of open listings have dead links.
- Report: before/after accuracy % per field, dead-link count, stale count removed, and sources fixed, saved at qa-v13.3/DATA-REPORT.md.

## 7. GRADER ACCURACY AUDIT — DO THIS LAST (after sections 1–6 are done and verified, so the 50-persona test runs on the final, fresh data) (the big one — this is our main feature)
Goal: grades must be realistic and consistent. No outliers, no grades that a recruiter would laugh at.

### 7-pre. Research first (before building personas or changing weights)
Research how employers actually screen interns, using real cited sources (NACE Job Outlook reports, firm recruiting pages, published acceptance or offer rates, reputable career-center and recruiting articles). Save the findings with links in qa-v13.3/GRADER-RESEARCH.md. Never invent stats; if a number isn't found, say so.
Cover:
- How selectivity differs by company tier (bulge bracket/elite boutique/MBB/FAANG vs mid-size vs local), including acceptance rates where published.
- How much GPA, school/target status, prior internships, leadership, technical skills and major matter, by industry.
- How employers value athletes (especially D1: time management, competitiveness, teamwork; known athlete recruiting pipelines in finance/sales) and other distinctive experience (military, startups/founding something, research, part-time jobs while in school, Greek or club leadership, first-gen).
Turn the findings into documented grader weights, with the source behind each weight.

### 7-curve. Company difficulty curve
- Give every company a selectivity tier (e.g., 1 = ultra-competitive: Goldman, Morgan Stanley, Evercore, McKinsey, Google, Jane Street; 5 = local/small). Base it on research and real signals (brand size, applicant volume, published acceptance rates). Store the tier and its reason in the company registry.
- The higher the tier, the harder an A or A+ is: raise the bar and compress the top grades, so only standout profiles (top school or strong GPA plus relevant prior internships) reach A at tier 1. Easy tiers stay achievable and don't hand A's to everyone.
- Show the tier in the detail panel ("Very competitive") so the grade makes sense.

### 7-exp. Experience types
- Give real credit for athlete status (D1 more than D2/D3/club, more weight for finance/sales/consulting where research supports it), leadership, military, founding something, research, and work while in school.
- Credit is modest and capped, it never outweighs GPA and relevant internships, and it's explained in the grade lines (e.g., "D1 athlete, valued in finance recruiting").
- The 50 personas must include athletes and these experience types, and the expected bands must reflect the research.

### 7a. Build a 50-student test set (tests/grader/personas.json)
Fictional test profiles (clearly test data, never shown to users). Spread across:
- Schools: ~10 elite (HYPSM, Wharton/Penn, Columbia, Duke...), ~10 strong (Michigan, UVA, NYU, Georgetown, Notre Dame...), ~15 mid (state flagships, regional privates like Queens), ~15 lesser-known/community college transfers.
- GPA: 2.5 to 4.0. Class years: freshman to senior.
- Experience: none, campus jobs, clubs/leadership, 1 internship, 2+ internships including big-name ones. D1 athletes included.
- Majors: finance, econ, CS, engineering, marketing, biology, undecided.

### 7b. Grade each persona against a fixed set of ~30 real listings from our database
Mix: bulge bracket/elite finance, big tech, mid-size companies, local/small firms, non-tech (marketing, healthcare, government). Use real listings only.

### 7c. Write expected bands BEFORE running
For each persona × listing pair (or a sampled 300+ pairs), set an expected grade band from common-sense recruiting reality (e.g., 2.6 GPA freshman, no experience vs Goldman IB summer analyst = D/F range; Wharton 3.9 junior with a prior IB internship vs a local accounting firm = A). Save as tests/grader/expected.json with a one-line reason each.

### 7d. Run, compare, fix
- Report: % of pairs in band, every outlier (off by 2+ letter steps), and patterns.
- Must also pass: for the same student, grades never go UP as company tier gets harder; no tier-1 A unless the profile is truly standout.
- Fix the grader in match-core.js until: ≥90% within band, ZERO pairs off by 2+ steps, and grade order is monotonic (better school/GPA/experience never grades LOWER, all else equal).
- Add a SLIGHT boost for stronger academic schools (tiered, modest — e.g., a few points, not a free pass) and for previous internships (more for relevant/selective ones, capped). These must not swamp GPA, skills and fit.
- Elite/selective listings must be harder; easy/local listings must not grade everyone as F.
- Sanity checks: same input always gives the same grade; missing data lowers confidence, not the grade itself unfairly; explanations (bars/lines in the detail panel) match the score.

### 7e. Keep it as a regression test
- tests/grader/run.js runs all 50 personas and fails if any outlier or monotonic break appears. Run it in CI (GitHub Actions) on every push touching match-core.js.

### 7f. Report back
- Before/after accuracy %, outlier count, list of weight changes and why, 5 example persona cards (profile, 3 listings, grades) to show Ty.
