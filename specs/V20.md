## PART 2 — Two host bugs this exposes (must fix, or 1a partially fails)

1. **`workday_alive()` only recognises `myworkdayjobs.com`.** Its regex is
   `myworkdayjobs\.com/(?:[a-z]{2}-[A-Z]{2}/)?[^/]+(/job/[^?#]+)`. Wells Fargo and Perella Weinberg serve from
   `wd1.myworkdaysite.com`. Result: every "is this still live" check for them returns `None` forever, so their
   postings can never be confirmed closed. Accept both hosts, and keep the tenant/site split from the registry slug.
2. **`discover.ats_from_url()` doesn't parse `myworkdaysite.com` either.** Its Workday branch is
   `([a-z0-9-]+)\.(wd\d+)\.myworkdayjobs\.com$`. A `myworkdaysite.com` URL therefore never becomes a registry row
   when it appears in a list. Add the same branch for `myworkdaysite.com`, where the path is
   `/recruiting/<tenant>/<site>/job/...` or `/<tenant>/<site>/job/...` — verify which against the two live hosts above
   and cover both.

Also: `pipeline/hygiene.py` line ~85 already has a `myworkdaysite.com/([...]/)?recruiting/[^/]+/[^/]+/job/...` pattern
for duplicate detection. Reuse that shape instead of writing a third variant.

### 3b. Himalayas API — with two conditions the terms require
`https://himalayas.app/jobs/api/search?q=intern&country=US` returned 757 results; in a 140-record sample, 139 had
"intern" in the title and all were US or unrestricted remote. 20 per request, cursor paging, `pubDate`/`expiryDate`.
Their terms require **a visible credit link** and **forbid passing their jobs to Google Jobs**. So:

- Rows from this source get `source_type: "api"` (or the closest existing value) and a `no_jsonld: true` flag.
- `pipeline/seo_pages.py` must skip any listing with `no_jsonld` when building JobPosting JSON-LD. The listing still
  appears on the company/category page as text; it just carries no structured data.
- Add a visible "Internships also found via [Himalayas](https://himalayas.app)" credit line with `rel="noopener"` on
  the page(s) that show those listings, and to `#about`'s data-sources paragraph.
- Their `applicationLink` is the required apply target for these rows.

### 3c. Radancy sitemap pages (UnitedHealth, Kaiser, and the next ones)

## PART 4 — Things the research found that are already wrong

1. **Evercore's tal.net board now returns an ALTCHA "Quick Check Needed" page** (4,800 bytes, zero vacancies)
   while Morgan Stanley's still serves its full board (128 KB, vacancies present). Today `talnet()` would read zero
   rows and the pipeline would mark Evercore's internships closed. Add a challenge check: if the response has no
   vacancy rows **and** its body matches a challenge marker (`ALTCHA`, `Quick Check Needed`, the widget script), return
   no rows and leave existing rows untouched with `check_unknown` rather than closing them. Same guard for any
   adapter: *an empty page is not an empty board.*
2. **Do not add the sources that failed**: Remotive, Arbeitnow, RemoteOK, Jobicy, Working Nomads, We Work Remotely
   (all ~0 US interns), governmentjobs.com (robots disallow), ExxonMobil RSS (`/services/` disallowed),
   Built In / Levels.fyi / YC / WayUp / internships.com (commercial HTML behind Cloudflare), Handshake (login).
3. **USAJobs**: the adapter exists and the key is free (email only, no card), but `data.usajobs.gov/robots.txt` is
   `Disallow: /`. Under the standing robots rule this stays **off** unless Ty says an official keyed API is an
   exception. Leave the adapter in place, unenabled, and note it in the report. Do not turn it on.
