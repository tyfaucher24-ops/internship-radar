# V19.4 — A real "on the site right now" count (heartbeat only, no UI on the site)

Spec by Radar. THOUGHTS, 2026-11-04. Small and separate from V20 (data coverage), so it can ship first.
Rules: $0, never invent data, keep guest mode and accounts working, keep every V18/V19 gain. Log in CHANGELOG as V19.4.

## Why
Ty wants a separate dashboard with total users, live users, and so on — off the Intern Index site. The dashboard
(its own repo, its own URL) is being built separately. This spec is only the part the Intern Index site has to do:
report that a person is on the site right now, and nothing that shows it to a visitor.

## What already exists
- `public.events` + `track_events` (migration 0005) records `visit` once per person per day. That is enough for DAU,
  not for "right now".
- `admin_stats_v17` is the aggregate the dashboard reads.
- Anonymous identity today: `public._caller_hash()` = signed-in uid, else the first `x-forwarded-for` address, hashed.

## 1. Database — `supabase/migrations/20261104000006_live_presence.sql` (already written, paste it)
- `public.live(who primary key, at, page, signed)`: one row per person, upserted, never selectable by clients,
  RLS forced, no grants to anon/authenticated.
- `heartbeat(p_page text)` — upserts one row keyed by `_caller_hash()`. `page` must match `^[a-z]{1,20}$` or it is
  stored null. Writes stop if the table ever holds more than 20,000 rows. 2% of calls delete rows older than a day.
- `admin_live()` — admins only (raises `not found`, errcode 42501, for everyone else). Returns
  `{now, five_min, signed_in, anon, by_page:[{page,n}], last_seen}`. `now` = distinct people seen in the last 90 s.
- Paste the file into the Supabase SQL editor in one go, in order after 0005. It is safe to run twice.

## 2. Client — send the heartbeat, show nothing
In `email-alerts.js` next to the existing `ev()` helper (same file, same connection logic, no new file):

- One function `beat(page)` that does `Cloud.rpc('heartbeat',{p_page:page})` when signed in, else the existing
  `anonRpc('heartbeat',{p_page:page})`. Wrap in `.catch(()=>{})` and set the `dead` flag on a 404 so a project
  without migration 0006 stops trying, exactly like `flush()` already does.
- Call it:
  - once on load,
  - on `radar:page` (the site already fires this when a tab changes),
  - on `visibilitychange` when the tab becomes visible,
  - and then on a 60-second timer **only while the tab is visible** (`document.visibilityState==='visible'`); pause it
    when hidden, no catch-up burst on return (the visibility handler already beats once).
- Never more than one beat per 45 seconds per tab, whatever the trigger.
- `page` is the current tab name only, lowercased and stripped to `[a-z]`: `db` for Find internships, `tracker`,
  `profile`, `autopilot` for Planner, `feedback`, `about`, `contact`, `privacy`, `terms`. Anything else sends `null`.
  Never a listing id, a query, a search term, an email, or a school.
- **Do Not Track / Global Privacy Control:** keep the existing rule. If `quiet` is true and the person is not signed
  in, do not beat at all. A person who asked not to be tracked is not counted.

## 3. Privacy page: one honest sentence
On `#privacy`, in the same section that explains the cookie-free counts, add: "So the site's owner can see how many
people are using it at once, each visit tells the server one thing: that someone is here, and which tab they are on.
It is a count that expires within a day. No cookie, no identifier that outlasts the visit, and nothing about what you
searched for or which internships you looked at."

## 4. Nothing visible
No new UI, no counter, no badge, no change to any page's look. A visitor must not be able to tell the difference.

## Acceptance
- With 0006 pasted, browsing Find, Planner, and Profile writes upserts to `public.live` and `select public.admin_live()`
  as an admin returns a sane object; as a non-admin it raises `not found`.
- Reload the page five times: `live` never gains more than one row for the same browser.
- Move between tabs for a minute: `page` follows the tab, and `now` stays 1 for one person.
- With Do Not Track on, signed out: `live` gains nothing. Signed in with DNT on: still one row.
- Sign out of Supabase (cloud off / `?cloud=0`): no heartbeat requests, no console errors.
- A 404 on the RPC (project without 0006) stops heartbeats after the first failure and breaks nothing else.
- axe: 0 violations on the pages touched (the privacy paragraph is the only visible change).
- Lighthouse mobile on Find: unchanged or better versus V19.2's 98.
- Screenshot of `public.live` row count and `admin_live()` output pasted in the report, with real numbers.
